# 机器人管理模块

本模块维护机器人档案及其与已登记 DS 的管理关系，不连接、控制或远程执行真实机器人。

## 当前真实能力

- MySQL 为每台机器人分配 `RB000001` 形式的稳定编号；
- 登记名称、机器人类型、序列号、IP 地址和备注；RB 编号由平台自动分配；
- 状态不在登记表单中编辑，新记录默认“在用”，后续只通过停用/恢复操作改变；
- 支持搜索、状态筛选、新增、编辑、停用与恢复；
- 名称和非空序列号不允许重复；
- 没有永久删除接口，停用记录仍保存在 MySQL；
- 一台机器人可关联多个 DS，一个 DS 同一时刻最多关联一台机器人；
- 已有数据集默认保持“未关联”，只能在机器人管理页关联、改绑或解除；
- `robot_type` 不一致仍允许关联，但页面会醒目提示；
- 停用机器人不能接收新关联，但可以查看历史数据集并解除错误关联；
- 新派生 DS 仅在所有来源 DS 都关联同一机器人时自动继承该关联。
- 新建机器人时自动生成一个采集上传 Token；每台机器人最多一个有效 Token；
- 创建机器人成功时，网页弹窗显示一次完整 Token，并提供复制按钮；
- 已配置 Token 的机器人可在网页重新生成；操作前明确确认，旧 Token 立即失效，
  新完整值在弹窗中显示一次；网页不提供删除或补充生成入口；
- 关闭弹窗后网页只显示 Token 是否存在、前缀、生成时间和最近使用时间；
- 完整 Token 仍可通过部署机终端查看、删除和重新生成，不能手工指定；
- 机器人停用后，已有 Token 立即不能调用机器上传 API。

## 文件职责

- `router.py`：页面、HTTP 参数和 API 状态码；
- `schemas.py`：档案和批量关联请求校验；
- `service.py`：机器人列表、关联清单、绑定、改绑和解除；
- `app/db/robots.py`：MySQL 表、稳定编号和读写操作；
- `app/db/dataset_robots.py`：DS 与 RB 的可选关系、历史来源继承和状态约束；
- `app/db/robot_tokens.py`：单机器人 Token 的生成、认证、终端显示与失效；
- `app/templates/robots.html`：页面结构；
- `app/static/js/robots.js`：注册、编辑、停用和恢复交互；
- `app/static/css/robots.css`：机器人页面样式。

## 当前边界

`network_address` 只是档案字段，不代表在线探测结果；`active` 表示“在用”，不是
实时“在线”。修改机器人类型或关联关系不会回写 LeRobot 数据集的 `meta/info.json`，
也不会改变 MySQL 中已有数据集的 `robot_type`。关系表保存的是平台管理元数据；
数据管理页只读展示采集机器人，不在那里修改关系。数据库中的旧 `model` 和
`sensors_json` 列暂时保留用于兼容既有部署，但新页面和 API 不再读写这些业务字段。
Token 是机器人调用 `/api/v1/collector/` 的机器凭证，不是网页用户登录密码；第一版
只允许可信内网 HTTP，不应直接暴露到互联网。
